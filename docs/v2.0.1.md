# v2.0.1 — focused literary reading update

This release retains the v2.0.0 layout, content, Quarto renderer, existing chapter
URLs, and GitHub Pages publication workflow.

## Changes

- Font controls now remain at the right of the sticky reading toolbar. A quiet
  vertical divider separates them from the reading modes. Default 17 px, range
  16–30 px, saved preferences, and 1.25× poem-title scaling are unchanged.
- Reading modes use consistent thin decorative SVG icons plus visible text,
  restrained color and underline selection, native buttons, and `aria-pressed`.
- Narrow screens use two toolbar rows, keeping both modes and size controls
  accessible without a floating dock over the poems.
- Poet openings have a 56 × 2 px muted olive-gray rule above the Russian name.
  It is decorative CSS and appears only on poet chapters.
- Biographies use Source Serif 4 at regular 18 px, line height 1.58, and a centered
  680 px maximum width with left-aligned paragraphs. Wording is untouched.
- Both existing Quarto chapter links are placed within the reading column, with
  explicit previous/next arrows that do not depend on the Bootstrap icon font.
  Native destinations and chapter order are preserved. The first poet links back
  to Home; the last poet's next link leads to the real book page.
- Superseded shared control styles were consolidated. No chapter source or image
  was edited, and no content transformation or normalization was introduced.

## Validation and release

Use `quarto render`, `python3 scripts/check_site.py`, and the browser acceptance
script documented in README. The one-time preservation audit compares all chapter
and image bytes with the pre-redesign tag; the Lua filter also checks text and
explicit line-break preservation during each render.

Browser checks cover desktop navigation expanded/collapsed; minimum, default,
intermediate, and maximum verse sizes; all modes; short and long lines; sticky
controls; 320, 375, and 430 px phones; keyboard activation and visible focus;
accessible names and selected-state semantics; and previous/next destinations.
Home and the real purchase page retain their existing content and artwork.

Manual VoiceOver/NVDA listening and physical iOS/Android browser checks remain
recommended: automated Chromium checks cannot fully verify those environments.

Publish the validated commit through the existing `main` workflow and verify the
live site before creating annotated tag `v2.0.1`. Earlier tags remain immutable.
